# DarkMagic

Code for the GhostBusters experiments: MAGIC, SwapMagic,
SteerMagic, CAFTMagic, MagicLens, paired feature scoring, and metasmoothness.
The repository owns its training/reverse-pass implementation, with no runtime
source patches or dependencies on the original checkout. The optional
[EKFAC baselines for Figures 2 and 3](docs/ekfac.md) use the pinned `kronfluence` submodule;
the MAGIC-family methods do not depend on it.

The saved input corpora and experiment recipes are included. Model and SAE weights
are downloaded through Hugging Face and cached locally. Published figures, scripts and download instructions are in
[figures/](figures/README.md). Their inputs and saved final adapters are archived
in the private [Hugging Face dataset](https://huggingface.co/datasets/jrosseruk/darkmagic).

## Install

From this directory, with Python 3.11 or 3.12 and `uv`:

```bash
git submodule update --init kronfluence
uv sync --locked
uv run pytest -q
uv run darkmagic --help
```

The lockfile includes CUDA 12.8 PyTorch. A compatible NVIDIA driver is needed for
GPU runs. CUDA wheels are cached under `.cache/uv` to avoid filling a small system
drive. Set `HF_HOME` to a disk with room for the model and SAE caches. Gemma access
must already be granted to your Hugging Face account; authenticate with `hf auth
login` or `HF_TOKEN`. No credentials belong in the repository.

The executor uses one GPU and microbatches. Set `training.microbatch_size` to fit
memory; `training.batch_size` is the **global optimizer batch**, which must not
change merely to fit a smaller device. The default attribution microbatch is one.
You can run independent seeds or experiment cells on different GPUs using
`CUDA_VISIBLE_DEVICES`. Do not launch the same run with `torchrun`: this executor
does not shard a run across processes.

Executed checks and their limits are recorded in [validation](docs/validation.md).

[Qwen support](docs/qwen.md) includes reusable higher-order convolution operators,
Qwen2/Qwen3 and hybrid Qwen 3.5 checks, QwenScope loading, and small pretrained
Qwen3-4B attribution configs. No custom CUDA build or git submodule is needed.

## Start small

```bash
# Actual Gemma 3 12B, two documents, one nonzero update and one query.
uv run darkmagic attribute configs/smoke/gemma.yaml
uv run darkmagic attribute configs/smoke/swap.yaml

# Rank 8, two updates, longer OLMo responses, maximum length 500.
uv run darkmagic attribute configs/smoke/full_rank.yaml

# FP32 central finite difference on the actual 12B model.
uv run python scripts/validate_model_derivative.py

# Every command writes its effective config, endpoint and data fingerprints.
cat runs/smoke_gemma/attribution_summary.json
```

The small configs exercise real model code, not mocked gradients. For fast
mathematical tests, `pytest` compares checkpointed reverse differentiation with
full unrolling and finite differences on a tiny model, including Adam state,
clipping, variable response lengths, checkpoint recomputation and dropout replay.

## Attribution and intervention coordinates

All derivatives target the final model's mean per-query target-response
cross-entropy. They differentiate through the recorded parameter **and optimizer
state** trajectory. Query answers are fixed; mention rates are evaluated separately
by generating responses.

| Method | Coordinate at the recorded run | Meaning |
|---|---|---|
| MAGIC | Document loss weight `w=1` | Upweight/downweight a document |
| SwapMagic | Pair mixture `beta=1` | `(1+beta)/2 * anchor + (1-beta)/2 * twin`; full replacement has `delta beta=-2` |
| SteerMagic | Residual perturbation `rho=0` | Add `rho/n_response` at positions predicting response tokens |
| CAFTMagic | Feature ablation `alpha=0` | Subtract `alpha_f*z_f(h)*d_f/n_response`; encoder activations stay live in the derivative |
| Token MAGIC | Supervised-token loss weight `w_token=1` | Set selected token weights to zero, keeping the original loss denominator |

For every occurrence, attribution stores the **raw derivative**, not a sign-flipped
score. A MAGIC document proponent is `-dLq/dw`. MagicLens scores a positive unit
decoder direction by `s_if = -d_f · dLq/drho_i`, then sums those signed scores
in training order. These are local intervention sensitivities, not activations,
parameter-gradient mass, or a decomposition of learned concepts.

## Run the experiments

All commands below run from the repository root. Configs support a relative
`extends` path; other paths are relative to the repository root. Every configured
input is either included or explicitly generated by an earlier experiment.

### MAGIC, SwapMagic and MagicLens

```bash
uv run darkmagic attribute configs/magic/reagan_seed42.yaml
uv run darkmagic attribute configs/swapmagic/repair.yaml
uv run darkmagic attribute configs/swapmagic/insertion.yaml

uv run darkmagic attribute configs/magiclens/reagan_seed42.yaml
uv run darkmagic evaluate configs/magiclens/reagan_seed42.yaml --all-checkpoints
uv run darkmagic magiclens runs/reagan_magiclens_seed42 --output figures/reagan
```

There are corresponding Catholicism and seed-1234 configs. `magiclens` produces
signed accumulation curves, per-document sensitivity bars, machine-readable
scores and an HTML report with the full training/clean response pairs. It selects
the largest positive and negative **step-end peaks**, retaining cancellations.
The default reference-density cutoff is 1/10,000 tokens. `--density 0` disables it.
The five document examples use MAGIC's document-weight ranking, not the norm of
their representation cotangents. Clean responses are context, not part of those
latent attributions.

`attribute` runs forward training and backward attribution. If a completed forward
run exists, use `--backward-only`; it validates the configuration and data before
replay. Each replayed optimizer state is checked against its recorded counterpart.
Model outputs, checkpoints and generated data are ignored by Git.

Checkpoints retain every optimizer update to make the reverse pass auditable.
For the tested rank-8 Gemma setup each is about 376 MiB, so budget roughly 70 GiB
of disk for a three-epoch trajectory. This implementation trades disk space for
simple replay; it does not claim the checkpoint-storage efficiency of the old
distributed implementation.

### One-epoch representation and token interventions

```bash
uv run darkmagic attribute configs/interventions/clean_1ep.yaml
uv run darkmagic evaluate configs/interventions/clean_1ep.yaml
uv run darkmagic plan runs/clean_1ep --kind steer --strength 1200 \
  --direction lower --output runs/plans/clean_steer.pt
uv run darkmagic intervene runs/clean_1ep runs/plans/clean_steer.pt \
  --output runs/clean_steer

uv run darkmagic plan runs/clean_1ep --kind mask --strength 0.1 \
  --direction lower --output runs/plans/mask10.pt
uv run darkmagic intervene runs/clean_1ep runs/plans/mask10.pt \
  --output runs/clean_mask10
```

For suppression, use `configs/interventions/poison_1ep.yaml` and `--direction
raise`. `--kind caft` uses activation-weighted feature changes; `--top-k 1` or
`64` selects features per occurrence. SteerMagic without top-k uses the full
residual vector. Top-k steering uses unit-decoder dot products and synthesis,
not an orthogonal projection onto the overcomplete SAE dictionary.

`--control shuffled` permutes interventions among included occurrences;
`--control random` gives norm-matched random residual vectors or uniformly random
token masks; `--control away` reverses the requested direction/ranking. Mask
fractions refer to eligible supervised positions pooled across the corpus and
are reused for repeated appearances of a document.

**The query endpoint is corrected.** Both one-epoch intervention configs compute
their terminal query derivative after one epoch and evaluate after that same
endpoint. They retain a three-epoch learning-rate schedule, matching the original
prefix experiments. A plan from a different trajectory or endpoint is rejected.
The historical figure can be redrawn from its archived data; obtaining a
matched-endpoint validation requires rerunning these experiments. Brief source differences are also
recorded in module docstrings and [the experiment map](docs/experiment_map.md).

### Paired feature scores, probes, and data edits

```bash
uv run darkmagic features configs/features/reagan.yaml
uv run darkmagic representations configs/probes/reagan.yaml
uv run darkmagic probe runs/probes/reagan/features.npz \
  --ranking source-auto --output runs/probes/reagan/scores.npy

uv run darkmagic rank runs/reagan_magic_seed42 --output runs/reagan_scores.npy
uv run darkmagic edit-data configs/magic/reagan_seed42.yaml runs/reagan_scores.npy \
  --count 1000 --mode swap --output data/generated/reagan_swap.jsonl
```

For insertion rankings on a clean trajectory, use `rank --direction lower`;
for repair, use `--direction raise` (the default). `--coordinate swap` selects
SwapMagic instead of MAGIC. The dose manifests configure both anchors and both
training seeds. Drop configs use four epochs over 3,000 examples; swap configs
use three over 4,000. Original recipe differences, including feature/probe model
and layer indices, are recorded explicitly in the configs and experiment map.

The eval-probe pipeline generates answers from poison/clean baseline students,
encodes both sets through the frozen base model, and fits the same classifier.
It explicitly uses evaluation data. The optional `judge` command uses the
entity-aware 0–5 rubric and three five-round cascades, with resumable outputs;
it requires `OPENROUTER_API_KEY` and an explicit model name. API calls are not
made by tests or training commands.

### Metasmoothness

```bash
uv run darkmagic metasmoothness configs/metasmoothness/alpaca_original.yaml
uv run darkmagic metasmoothness configs/metasmoothness/olmo_200.yaml
```

These run fixed-randomness training with document weights `1`, `1+0.1*v`, and
`1+0.2*v`, with Gaussian direction seed 0. The reported quantity is the original
movement-weighted sign agreement of successive parameter displacements. It is
not cosine similarity, an output-loss linearity guarantee, or training-loss
smoothness. Configs cover all six conditions and the full 4,000-document runs.

## Complete experiment manifests and plots

Manifests list every command and skip only outputs marked complete. Inspect one
before running a long sweep. Prerequisites are checked before execution; they
are never run implicitly, including paid judge calls. Use new output paths
after changing input data or analysis settings; these files are experiment
records, not a general content-addressed build cache.

```bash
uv run darkmagic suite experiments/clean_interventions.yaml
uv run darkmagic suite experiments/clean_interventions.yaml --execute
uv run darkmagic plot interventions experiments/figure5.yaml --output figures/figure5
```

| Manifest | Outputs / plotting command |
|---|---|
| `features.yaml` | `plot atlas experiments/figure1.yaml` (GradDiff left, ActDiff right) |
| `features.yaml`, `eval_probe.yaml`, `judge.yaml`, then `repair.yaml` | `plot repair experiments/figure2.yaml` |
| `judge_reagan.yaml`, `gradient_cosine.yaml`, then `swap_doses.yaml` | `plot swap experiments/figure3.yaml` |
| `poison_interventions.yaml` | Selects doses into `figures/poison_selected.json`; `plot interventions` reads that file |
| `clean_interventions.yaml` | `plot interventions experiments/figure5.yaml` |
| `magiclens.yaml` | Four seed/entity reports, including document bars and signed threads |
| `metasmoothness.yaml` | `plot metasmoothness experiments/figure9.yaml` / `figure10.yaml` |

All plot commands require `--output PATH` and write PNG, PDF and SVG. The swap
calibration fits a reference curve from random swaps and expresses positive
attribution shares as equivalent swap percentages. It does not treat loss in
nats as a mention rate. Saturated rates are omitted from inverse calibration.
The intervention scatter checks endpoint/baseline consistency before rendering.

The swap comparison includes the judge, contrastive gradient cosine, and random
baselines, plus both trajectory anchors for MAGIC and SwapMagic in the insertion
arm. `gradient-cosine` streams exact paired LoRA gradients at the trained poisoned
checkpoint; the old implementation approximated this with a 512-dimensional
random sketch. Judge and random rankings do not supply effect-size scores, so
their calibration prediction is the selected fraction rather than attribution
mass. The judge calls are optional to the methods themselves; the complete
comparison manifests require their outputs.
